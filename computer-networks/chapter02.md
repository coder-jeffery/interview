2. 路由器、交换机、网关分别工作在哪一层？要点：路由器在网络层，交换机在链路层，L7 网关在应用层。
        路由器：网络层
        交换机：数据链路层
        网关：应用层 传输层 
        集线器：物理层
**二、TCP（最高频）**

3. ⭐ 三次握手的过程，为什么是三次而不是两次？要点：双方都要确认自己和对方的收发能力；只握两次的话，历史上残留的 SYN 会建立无效连接。
         SYN，SYN+ACK,ACK 状态回传，全双工通信
4. ⭐ 四次挥手的过程，为什么是四次？要点：TCP 是全双工，两个方向要分别关闭；被动方可能还有数据没发完。
        SYN，SYN+ACK，ACK，确保信道正常
5. ⭐ TIME_WAIT 为什么要等 2MSL？大量 TIME_WAIT 怎么处理？要点：保证最后一个 ACK 能被对方收到，并让旧报文在网络中消失；处理上可以用长连接、开 `tcp_tw_reuse`、调整端口范围。
6. CLOSE_WAIT 大量堆积说明什么？要点：应用没有调用 `close`，基本是代码 bug。
7. ⭐ TCP 如何保证可靠传输？要点：序号、确认应答、超时重传、快速重传、校验和、滑动窗口、流量控制、拥塞控制。
8. ⭐ 流量控制和拥塞控制有什么区别？拥塞控制有哪些算法？要点：流量控制保护接收方，拥塞控制保护网络；算法包括慢启动、拥塞避免、快重传、快恢复，以及 Cubic 和 BBR。
9. 半连接队列和全连接队列是什么？SYN 洪水攻击怎么防？要点：开启 SYN Cookie，调大 backlog。
10. ⭐ 粘包和半包的原因及解决办法？要点：TCP 是字节流，没有消息边界；用定长、分隔符或长度前缀在应用层定义边界。
            TCP有状态，粘包：重复，有序，超时重传，没有消息边界，字节流
11. Nagle 算法和延迟 ACK 叠加会有什么问题？要点：小包场景会多出约 40ms 延迟，可以用 `TCP_NODELAY` 解决。
12. TCP keepalive 和 HTTP keep-alive 有什么区别？
        TCP keeplive：传输层
        HTTP keep-live：应用层 利用TCP多路复用 控制头： `Connection: keep-alive` / `Connection: close`

            UDP无状态 ，数据报｜ 不保证到达，不重复或有序

15. ⭐ 从输入 URL 到页面展示，中间发生了什么？要点：依次是 DNS、TCP、TLS、HTTP 请求、服务端处理、响应、浏览器渲染，每一步都可能被深挖。
16. ⭐ HTTP/1.0、1.1、2、3 的区别？要点：1.1 有长连接和管道化；2 有二进制分帧、多路复用、HPACK；3 基于 QUIC，解决了 TCP 层的队头阻塞。
17. ⭐ HTTPS 的握手过程？TLS 1.2 和 1.3 有什么区别？要点：涉及证书校验、密钥交换、对称加密；1.3 握手只要 1-RTT，还支持 0-RTT。

19. GET 和 POST 有什么区别？要点：语义、幂等性、是否可缓存，而不是只说"参数放的位置不同"。
20. 常见状态码有哪些？301 和 302、401 和 403、502 和 504 分别有什么区别？要点：502 是网关收到了上游的错误响应，504 是网关等上游超时。
21. 强缓存和协商缓存是什么？要点：强缓存看 `Cache-Control`、`Expires`；协商缓存看 `ETag`、`Last-Modified`。
