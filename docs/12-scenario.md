# 项目深挖与场景题

> 面试权重：决定中高级去留  
> 适合层级：3 年+ 为主；校招把「项目」换成实习/课程设计同样适用

原理题过关只说明你背过书。中高级第二轮通常是：**把简历上的系统拆开，看你是否真的做过。**

## 项目怎么讲（8–12 分钟）

用这条骨架，不要按时间流水账：

1. **背景与约束：** 谁用、量级、一致性要求、不能停机。  
2. **你的边界：** 你做了哪几块，不是「我们组做了微服务」。  
3. **关键设计：** 最多 2 个点（例如：库存预扣 + 异步出库；或：慢查询 + 缓存）。  
4. **证据：** QPS、数据量、P99、事故、对比基线。  
5. **取舍：** 放弃了什么方案。  
6. **复盘：** 下次会改哪里。

数字准备三套口径：峰值/日常、单机/集群、优化前后。被问「怎么测的」要答得出压测工具、数据是否生产脱敏、有没有预热。

## 面试官常用深挖链

从任意项目里，他们可能沿这条链往下走。每一环准备 60 秒：

```text
流量从哪进 → 鉴权 → 限流 → 服务 → 缓存 → DB → 消息 → 对账
         ↘ 超时怎么设    ↘ 缓存失效    ↘ 慢 SQL     ↘ 重复消费
```

简历出现「秒杀 / 优惠券 / 支付 / 导入导出 / 报表 / 同步任务」，几乎必问对应那一环。

## 场景题答法

先澄清再设计。缺的信息就问，不要假装系统已经是双活全球。

最少问清：

- 读写比、峰值、是否允许短暂不一致  
- 数据量、是否要按用户隔离  
- 失败时用户看到什么（错误、排队、降级）

然后给 **能上线的最小方案**，再加演进（缓存 → 分库 → 多活）。

---

## S1: 接口突然变慢

**口述**  
先看是全部接口还是某一个；是某实例还是全集群；是否发布/过期/大促对齐。  
并行看：网关 RT、服务 RT、DB/Redis/下游 RT、GC、线程池队列、CPU。  
常见：慢 SQL、缓存失效击穿、连接池耗尽、Full GC、下游超时重试放大、磁盘满打日志。  
处理：限流保核心、扩容只是买时间、找到依赖再回滚或加索引。

**追问准备：** 你用过的看板（Grafana 哪几张图）、一次真实慢查询的 `EXPLAIN`。

## S2: 缓存与数据库不一致

**口述**  
承认窗口必然存在，选可接受延迟。  
常见策略：Cache Aside（写库后删缓存）+ 订阅 binlog 删缓存；延迟双删只能减小窗口。  
读多写少用缓存；写多或强一致路径绕过缓存或短 TTL。  
千万别「先更新缓存再写库」当通用方案。

## S3: 超卖 / 库存

**口述**  
单机：DB 条件更新 `WHERE stock >= n`。  
高并发：Redis 预扣（Lua 判断库存）+ 异步落库 + 对账补偿。  
超卖零容忍还要靠 DB 约束或单分片串行。  
售罄后的读用缓存打底，避免打穿。

**追问：** 下单未支付怎么还库存（延迟消息）；Redis 丢了怎么和 DB 对。

## S4: 重复提交 / 支付回调

**口述**  
前端防抖不够。后端：同一业务键唯一索引；支付回调验签 + 状态机。  
MQ 消费者同样按业务键幂等。  
回调乱序：以支付单状态为准，不能假设通知顺序。

## S5: 热点账号 / 热点商品

**口述**  
读热点：本地缓存 + Redis 多副本随机前缀。  
写热点：打散（库存分桶再汇总）、队列串行化单 key。  
数据库：热点行锁等待，表现为 RT 高而 CPU 不高。

## S6: 数据导入 1000 万行

**口述**  
不要同步 HTTP 一次做完。上传 → 落对象存储 → 任务队列 → 批量 INSERT（大小要试）→ 失败行可重跑。  
唯一键去重。进度表。限速保护线上 DB。  
深分页用 seek。必要时离线数仓/夜间窗口。

## S7: 系统要「高可用」

**口述**  
先定义：几个 9、RPO/RTO、是否跨机房。  
无状态服务多副本 + 就绪探针。有状态：MySQL 主从 + 备份；Redis 哨兵/集群。  
依赖都可能挂：超时、熔断、降级开关。  
多活是最高成本方案，不要一上来画。

## S8: 权限与安全（常被忽略）

**口述**  
水平越权：只校验登录不够，要校验资源归属。  
接口鉴权放网关 + 服务内二次校验。  
敏感配置不进 Git。日志打码。上传校验类型与大小。  
SQL 用参数绑定。这些讲出来比「我们用了 Spring Security」更像做过。

## 把项目映射到本仓库

准备项目时，强制自己填这张表（写在纸上，不要贴进公开简历）：

| 系统里的点 | 对应章节 | 我能讲到哪一层 |
|------------|----------|----------------|
| 缓存 | Redis | 穿透/击穿是否真的发生过 |
| 订单状态 | MySQL 事务 / 幂等 | 状态机有哪些非法跳转 |
| 异步发货 | MQ | 丢失/重复/积压处理过没有 |
| 变慢 | JVM / 慢 SQL | 有没有 GC 日志或 EXPLAIN |
| 发布 | 分布式 | 优雅下线做过没有 |

填不出证据的格子，面试就不要用「精通」开口。
