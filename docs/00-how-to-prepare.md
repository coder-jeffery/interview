# 备战策略

> 面试权重：贯穿全程  
> 适合层级：所有人

背题只解决「会不会」。中高级面试淘汰的是：**简历写过但讲不深、原理说得出但没排过障、方案只有正确没有取舍。**

## 按层级选范围

| 层级 | 必须能讲透 | 可以只懂概念 | 不要假装精通 |
|------|------------|--------------|--------------|
| 校招 / 1–2 年 | Java 基础、集合、MySQL 索引/事务、HTTP/TCP、Spring 注入与 MVC | 并发关键字、Redis 缓存、简单 JVM 内存图 | 微服务全家桶、自研中间件 |
| 中级 3–5 年 | 并发、HashMap/CHM、事务失效、Redis 三连、慢 SQL、一次线上排查 | JVM 收集器对比、MQ 可靠性、限流熔断 | 「我设计了公司级注册中心」 |
| 高级 5 年+ | JVM 调优证据、分布式一致性取舍、容量/稳定性、带数字的项目结果 | 新语言特性、云原生细节 | 背诵每一个 JEP 编号 |

**原则：** 简历出现过的词，深度必须高于本章「30 秒答法」。没写过的，用「了解」而不是「精通」。

## 两周冲刺节奏（在职）

假设每天有效 1.5–2 小时：

| 天数 | 做什么 |
|------|--------|
| 1–2 | 把简历 technotes 标红：每个词对应到本仓库章节，标「能讲 / 半会 / 不会」 |
| 3–6 | 不会的必会章：集合、MySQL、Redis、并发。每题自己录音 30 秒 |
| 7–9 | Spring 事务/循环依赖 + 项目深挖（QPS、数据量、事故、指标） |
| 10–12 | JVM 或 MQ/分布式，按目标公司选一条深挖 |
| 13–14 | 模拟面试：项目 20 分钟 + 原理 20 分钟 + 场景 10 分钟 |

校招把「项目深挖」换成算法（数组/哈希/链表/树/二分等基础题），原理深度降一档。

## 简历红线

面试官拿到简历后，通常 30 秒决定问什么。下面这些写法几乎必被追问：

- 「负责系统架构」→ 问你画过的图、取舍、失败过什么。
- 「QPS 十万」→ 问峰值口径、机器数、是否缓存、是否预热、打满了怎么办。
- 「使用 Redis 分布式锁」→ 问 Redisson 看门狗、主从误锁、业务超时。
- 「优化 SQL，性能提升 10 倍」→ 问原 SQL、执行计划、索引、有没有把慢查询转移到别的地方。
- 「精通 JVM」→ 直接上 GC 日志、参数、一次 OOM/CPU 飙高的排查路径。

数字要经得起反问：**口径、时间窗口、对比基线、代价。** 没有数字就写清范围（「核心链路 P99 从 800ms 降到 200ms，代价是多 2 台缓存」）。

## 面试官在听什么

1. **边界意识**：你知不知道方案在什么条件下会坏。
2. **证据**：日志、指标、执行计划、压测，而不是「我觉得」。
3. **取舍**：为什么不用更简单的办法。更简单的办法说不出来，说明没想过。
4. **协作**：事故里你做什么、别人做什么、事后改了流程还是只改了代码。

## 现场答题顺序

原理题：定义 → 场景 → 机制 → 坑。  
对比题：先说相同点（都是锁 / 都是缓存），再按「功能、性能、失败语义、运维成本」四维对比。  
场景题：澄清流量与一致性要求 → 给能上线的最小方案 → 说出瓶颈和下一步。不要一上来画微服务全家桶。

## 反问面试官（建议准备 2 个）

- 这个岗位近期最痛的稳定性/性能问题是什么？团队现在怎么看？
- 入职 90 天，你们期望我独立扛住哪条业务链路？

反问是信号：你在评估工作，而不只是求通过。
